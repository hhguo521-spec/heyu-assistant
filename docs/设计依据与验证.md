# 禾予种草助手 页面设计依据与验证

## 目标与证据来源

让首次访问者理解工具的用途，顺利填写创作需求，知道等待时如何操作，并能识别发布前需要人工复核的信息。视觉方向参考 [Readymag 的视觉叙事与排版](https://readymag.com/editorial) 和 [Framer 沉浸式网站案例](https://www.framer.com/community/gallery/vibe/immersive/)，采用原创编辑部式构图，不复制案例。首页素材由 imagegen 基于“蓝色半透明带状雕塑、暖白纸面、红色小球与摄影光影，无文字、无商品与人物”的描述生成。

原始依据包括：现有站点的表单和生成代码、Dify 导出的工作流与输入输出、用户提供的视觉参考、实际生成图片与评测结果，以及用户对标识漏检的反馈。此前的图片评测仅表明两条特定案例存在评估分歧，不能证明新设计提高转化率或整体图片质量。没有进行用户访谈、真人测试或线上行为统计。

## 专业设计会额外做的事

- 用未经引导的任务观察真实使用者，检查首次访问、提交、等待、异常恢复、复制及发布前复核，不只评判视觉。
- 验证不同屏幕、键盘、读屏、低性能设备和弱网络，检查动画和素材加载是否影响操作。
- 对自动审核、人工复核与业务真实性建立清晰边界；保留出错时任务编号和查询入口，避免重复提交。
- 比较修改前后的相同任务及衡量方式，在有限证据下判断而非直接假定设计成功。

## 本次设计假设与修改

| 原始观察 | 设计决定 | 待验证假设 |
| --- | --- | --- |
| 旧首页的抽象标语未直接说明服务对象和输出 | 首页写明扫地机器人、文案、配图和视频，加入创作入口与三步说明 | 新访客更容易理解用途 |
| 原自动通过描述可能被误会为图片、价格均已核验；两张原图也有疑似标识争议 | 结果旁提醒人工核对商品信息、价格和画面 | 用户更容易意识到核对责任 |
| 视频镜头只适用于视频；未选视频时它增加阅读负担 | 只在选择含视频时显示该输入，切换时不提交隐藏值 | 用户更容易理解输入用途 |
| 生成可能持续至 6 分钟，超时后任务可能仍运行 | 保留进度、任务编号、再查一次和避免刷新提示 | 用户不容易误以为需要重复提交 |

## 方法与工具

使用任务流程与启发式检查、页面内容层级、HTML 语义与键盘焦点、响应式布局，以及隔离模拟服务测试成功与转人工结果。测试使用浏览器可访问性树、桌面和移动视口、对比度计算、Node 测试和项目构建。参考 [WCAG 2.2](https://www.w3.org/TR/WCAG22/)；自动化检查不能取代人工无障碍检查，见 [W3C 对评估工具的说明](https://www.w3.org/WAI/test-evaluate/tools/selecting/)。

## 独立证明与后续验证

1. 邀请至少 5 位目标使用者，在没有操作提示的情况下完成：说出工具用途、填写一次创作需求、选择不含视频的输出、找到生成结果并解释发布前应检查什么。记录完成情况、时间、错误与原话；再用同一任务比较旧版。样本量小只用于发现问题，不作为统计意义上的提升证明。
2. 让未参与设计的人按真实手机、桌面、键盘和屏幕阅读器检查导航、错误和结果；结合自动无障碍工具检查，保留问题和修复记录。
3. 在获授权的情况下观察真实网络和设备的加载、失败、重复提交情况；不收集口令及敏感内容。可参考 [Web Vitals 测量说明](https://web.dev/articles/defining-core-web-vitals-thresholds/)；实验室结果不能当成真实用户数据。
4. 本地模拟测试不调用 Dify，也无法证明线上密钥、模型或第三方服务实际可用；线上要由具备口令的使用者完成一次真实端到端试用。图片和商品信息仍需人工复核。
